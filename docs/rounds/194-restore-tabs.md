# M9：被杀之后恢复标签页（2026-11-02）

← [M9：以指定用户登录（2026-11-02）](193-login-account.md) · [索引](../milestones.md) · [M9：进程被结束、服务没起来时提示（2026-11-02）](195-kill-reports.md) →

设计文档 §11.2 的"进程被杀"：v1 只恢复标签页布局、每个标签页的当前目录和回看记录，起新的 shell，明确提示"上次会话因 App 被系统终止而结束"，不恢复进程。M9 计划里的三件之一。

## 做法

### 什么时候算"被杀"（`Tabs.kt`）

内核起来之后在 `files/tabs/` 留一个"在运行"的标记，正常退出（`exitAll` 关机完成、服务 `onDestroy`）时连同存下的标签页一起删掉。服务启动时标记还在，就是上次没有正常退出：被系统杀掉了，或者崩溃了（App 升级时进程被结束也算）。这时读回存下的标签页，等内核第一次起来之后恢复；标记去掉，内核起来时再留。

### 存什么、什么时候存

每个还在运行的标签页存三样：

- **登录账号**：这个标签页当初用的（`auto`、`root` 或账号名），恢复时照用，不跟着现在的设置。
- **当前目录**：控制台前台进程组的当前目录。新的 `Machine::console_cwd`（`terminal::fg_cwd`）取 PTY 的前台进程组，组长的（组长退出了取组里任意一个进程的）`fs.cwd`，按那个进程的根目录算路径，与它的 `/proc/<pid>/cwd` 一样。正在 vim 里时是 vim 的目录，一般与 shell 的相同。shell 已经退出的标签页不存。
- **回看记录**：终端模拟器的 `getTranscriptText()`（纯文本，自动换行的行接回一行，恢复时按新的宽度重新折）。最多存最后 256 KB。

另外记下当前显示的是第几个、存的时刻。存的时机：

- 内核运行期间每 60 秒一次；
- 界面隐藏（最后一个 Activity 停下）时马上存：被杀多半发生在后台；
- 内存紧张（`onTrimMemory`）时；
- 开、关标签页之后 2 秒（接连几次只存一次）。

回看记录在主线程上取（模拟器在主线程上改），取当前目录要拿 BKL，和写文件一起在 `worker` 上做。每个文件先写临时文件再改名，最后写索引；内容没变的文件不重写（按散列比，每分钟一次也不会一直写闪存）。恢复出来、还没显示过的标签页模拟器还没建，存的是原来那一份。

### 恢复

内核起来之后、通知界面之前，每个存下的标签页以原来的账号新开一个会话，从原来的目录开始，在 shell 启动之前先显示原来的回看记录（`\n` 换成 `\r\n`），再一行黄色的提示："[appine] 上次会话因 App 被系统终止而结束（标签页保存于 11/2/26 9:51 PM），之前运行的程序没有恢复。"界面显示原来正在看的那个标签页。

- vendored 的 `TerminalSession` 加了两个方法：`setRestored`（模拟器建好之后、shell 启动之前 `append` 进去，显示过就丢掉）和 `getTranscriptText`。模拟器在标签页第一次显示时才建，所以没显示过的标签页也能这样先放着。
- **从原来的目录开始**：`login.sh` 多一个参数（目录）。root 直接 `cd` 过去；普通用户原来用 `su -l`，它总是回家目录，改成 `su 账号 -c 'exec "$SHELL" -l'`（不换目录，su 照样设好 HOME、SHELL、USER、LOGNAME），目录在 `-c` 的命令里以这个账号的身份进（root 进得去的 `/root` 它进不去），进不去回家目录。目录名里的单引号转义过。
- `/etc/profile.d/appine.sh` 原来最后有一行 `cd "$HOME"`，会把恢复的标签页带回家目录。新开的标签页从家目录开始改由 `login.sh` 负责，profile 里去掉这一行。之前导入的仓库里 App 写的那份没被改过的，启动内核之前换成新的（`Rootfs.updateProfile`，用新加的 `Native.readFile` 比对原文）。

## 测试

- 仪器测试（Pixel 4a、API 34 的模拟器）新增三个：
  - `loginStartsInTheSavedDirectory`：root 从 `/etc` 开始；目录不在了回 `/root`；不给目录是家目录；alice 从 `/usr/share` 开始，给 `/root` 时回 `/home/alice`。
  - `consoleCwdFollowsTheForegroundShell`：登录之后是 `/root`，输入 `cd /usr/lib` 之后是 `/usr/lib`，shell 退出之后取不到。
  - `tabsComeBackOnlyAfterAKill`：留了标记、存过之后读回原样（账号、目录、回看记录、当前是第几个），读过一次标记就没了；正常退出（clear）之后读不到。
  - 21 个里 20 个通过，`downloadedDistributionsRun` 照例默认跳过。第一次跑时有 4 个失败：模拟器上留着上一轮手动测试建的 alice（重装 App 不清数据），"自动"都以 alice 登录了；留着的 profile 还是旧的，测试自己起内核时没有像 App 那样先迁移。测试的准备步骤里也调用 `Rootfs.updateProfile`，在干净的数据上重跑都通过。
- 手动（模拟器上的 App）：开两个标签页，一个 `cd /etc` 再列几个文件，一个 `cd /usr/lib`；回桌面（存了一次：`index.json` 里是 `/etc`、`/usr/lib`，当前是第 2 个），`am force-stop` 结束进程（不给 App 回调，与被系统杀掉一样）。再打开：两个标签页都在，显示的是第 2 个，原来的输出后面是黄色的提示，新的提示符是 `root@localhost:/usr/lib#`；第 1 个是 `/etc`。之后在通知里点"全部退出"：`files/tabs` 删掉了，再打开是一个新的标签页、没有提示。
- `cargo test --workspace`、clippy（整个工作区和 Android）、格式通过。内核层只加了 `console_cwd`，guest 看到的行为没变，没有重跑差分测试和 LTP。只在 4K 页的模拟器上跑了。

**推迟项**：

- 回看记录是纯文本：颜色、粗体这些样式没有存，恢复之后都是默认颜色。
- 存的是每分钟（和界面隐藏时）的状态：界面开着时被杀，最后一分钟之内的输出和 `cd` 会丢。
- 关掉了最后一个标签页、靠后台服务留着的 App 被杀之后，没有标签页可恢复，也就没有提示；后台的服务（OpenRC 起的）会在下次开机时照常起来。
- 用户自己"强行停止" App 也被当作被杀，下次会恢复：Android 不告诉 App 是谁结束了它。
- 正在全屏程序（vim、less）里时存的是它的屏幕内容和目录，恢复后只有文字，程序本身没了。
- 标签页的标题（程序用 OSC 序列设的）没有存，恢复之后由新的 shell 再设。
